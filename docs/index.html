OpenContest Documentation

OpenContest — модульная платформа для проведения соревнований по спортивному программированию и тренировок в стиле Codeforces и Yandex Contest.

Включает веб-интерфейс на React 18 / Tailwind, REST API на Django, очередь RabbitMQ, масштабируемые раннеры на Go в песочнице nsjail, Docker Compose для запуска одной командой и манифесты Kubernetes с KEDA-автоскейлингом.

React / Vite Django REST Framework PostgreSQL RabbitMQ Go Runner nsjail sandbox Docker Compose K8s & KEDA

Быстрый старт

OpenContest запускается одной командой через Docker Compose:

# Клонируем репозиторий
git clone https://github.com/Shyambf/OpenContest.git
cd OpenContest

# Создаём локальный .env из шаблона
cp .env.example .env

# Запуск на Linux / macOS
./scripts/dev.sh

# Запуск на Windows (PowerShell)
.\scripts\opencontest.ps1 start

После успешного старта будут доступны следующие адреса:

  • Frontend веб-интерфейс: http://localhost:5173
  • Backend REST API: http://localhost:8000/api
  • Health Check: http://localhost:8000/api/health/
  • RabbitMQ Dashboard: http://localhost:15672 (логин/пароль: guest / guest)
Демо-пользователи:
  • Администратор: логин admin, пароль admin123
  • Участник: логин coder, пароль coder123

Масштабирование воркеров (Runners)

Количество параллельных тестирующих воркеров (раннеров) настраивается напрямую через переменную RUNNERS_COUNT в файле .env: 

# В файле .env задайте желаемое количество воркеров
RUNNERS_COUNT=3

При выполнении docker compose up (или запуске скрипта) автоматически поднимется указанное количество реплик:

# Запуск через PowerShell с флагом количества раннеров:
.\scripts\opencontest.ps1 start -Runners 3

Каждый раннер получает уникальный идентификатор вида runner-<container_id>, подключается к RabbitMQ и независимо забирает посылки из очереди.

Архитектура системы

1. Frontend

SPA на React 18 / TypeScript / Vite с тёмной терминальной темой, редактором кода, графиками рейтинга и адаптивной версткой.

2. Backend API

Django 5.2 / DRF сервер: аутентификация по токенам, банк задач, контесты, Q&A (clarifications), лидерборд и Server-Sent Events.

3. Message Broker

RabbitMQ с очередями judge.submissions (задания на проверку) и judge.results (вердикты тестирования).

4. Go Runner

Компиляция и исполнение кода в песочнице nsjail для языков C++17, Python 3, Java 17 и Rust.

Runner и Sandbox (nsjail)

Раннер написан на Go и обеспечивает максимальную изоляцию выполнения пользовательских решений с помощью легковесной песочницы nsjail (Google).

Поддерживаемые языки:

  • C++ 17: Компиляция g++ -O2 -pipe -static
  • Python 3: python3 main.py
  • Java 17: javac Main.java, запуск с лимитами кучи JVM
  • Rust: Компиляция rustc -O main.rs

Языки конфигурируются декларативно в файлах runners/go-runner/languages/*.json, что позволяет добавлять новые компиляторы без изменения исходного кода раннера.

Панель управления (Admin Panel)

Доступна администраторам по адресу /admin в веб-интерфейсе:

  • Монитор раннеров: отображение всех активных воркеров, их аптайма, нагрузки, числа обработанных задач и текущего статуса.
  • Управление контестами: создание олимпиад, назначение задач, настройка времени тура и правил подсчёта.
  • Банк задач: создание, редактирование ограничений, просмотр тестов и импорт архивов задач.
  • Управление решениями: ручной пересчёт вердиктов (override), rejudge и дисквалификация нарушителей.

Kubernetes и KEDA

Манифесты для развёртывания в кластере находятся в каталоге deploy/k8s/.

# Развёртывание в кластере:
kubectl apply -k deploy/k8s

С помощью KEDA (Kubernetes Event-driven Autoscaling) воркеры автоматически масштабируются от 1 до 50 подов в зависимости от количества неразобранных сообщений в очереди RabbitMQ.

Безопасность и аудит

В рамках проекта ведётся систематический аудит безопасности. Полный отчёт доступен в файле SECURITY_AUDIT.md репозитория.

Основные меры защиты:

  • Изоляция сетевого стека решения (отсутствие доступа в интернет);
  • Ограничение по времени CPU, памяти и размеру генерируемых файлов (rlimit);
  • Защита от fork-бомб (лимит количества процессов nproc);
  • Разграничение прав участников и администраторов через роли Django.

Нагрузочное тестирование

В репозитории есть встроенный скрипт для генерации потока решений:

# Запуск генератора 100 посылок в 10 потоков:
OPENCONTEST_LOAD_COUNT=100 OPENCONTEST_LOAD_WORKERS=10 python3 scripts/load_test.py
